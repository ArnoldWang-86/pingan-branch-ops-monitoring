# 任务：构建一个 Text-to-Excel Agent（单文件离线网页）

## 一、你要交付什么

**一个 HTML 文件。** 用户双击打开后：

1. 在页面里用**中文自然语言**提问；
2. **左边**实时逐步展示 Agent 的**完整工作流程**（不是只给结果）；
3. **右边**给出结果：关键指标卡、图表、明细表；
4. 最后可以**下载一个真正能打开、带格式的 `.xlsx` 文件**。

**硬性约束（逐条都要满足，不可商量）：**

- **单文件**。所有数据、所有依赖库、所有逻辑都必须内联在这一个 `.html` 里。
- **离线可用**。断网、无后端、无服务器，双击 `file://` 打开即用。
- **无外部请求**（唯一例外见第六节的可选 API Key 输入）。
- Excel 必须是**真 `.xlsx`**，能被 Excel / WPS / Numbers 直接打开，不含宏。

## 二、最重要的一条设计原则：不让 LLM 写代码

**Agent 的核心结构必须是：**

```
自然语言 → 意图识别 → 从「操作白名单」里选一个 + 填参数 → 受控执行 → 生成 Excel
```

**绝对不允许**让 LLM 生成可执行代码（不许生成 pandas 代码、不许生成 SQL、
不许 `eval` 任何模型输出）。

模型只能做两件事：
1. 从**预定义的 N 个操作**里选一个；
2. 为这个操作**填参数**，参数会被**逐项校验取值范围**。

**为什么这条最重要**：这样从结构上排除了代码注入与模型幻觉带来的风险。
这是与「让模型自由写分析代码」的本质区别。
**并且要把这一点直接写在页面上给使用者看**，不要藏在代码注释里。

## 三、领域数据与语义层

### 3.1 数据

数据源：`[在这里写你的数据来源、文件路径、规模]`

示例（我做银行网点运营时的情况）：
> 数据是 20 家银行网点 × 90 天 = 1,800 条日运营记录，CSV 格式，
> 每条记录包含日期、网点、类型、窗口数、业务量、等候时长、差错笔数、
> 投诉笔数、满意度、成本收入比等 71 个字段。

**如果数据量较大（> 500 KB）**，按下面处理后再内联：
- 只保留分析真正会用到的列；
- 数字做定点舍入（比率 4 位、时长 1 位）；
- 用**列式存储**（每列一个数组），比行式 JSON 小约 40%；
- 另存一份 `window.XXX_DATA = {...}` 的 `.js` 文件，构建时内联进 HTML。

### 3.2 语义层（**这一步绝不能省**）

**在动手写代码之前**，先产出一份 `semantics` 模块（可以是 JS 常量，也可以是 Python 文件），
把下面三件事写清楚：

**(a) 数据性质声明** —— 必须能回答"这些数据是什么、能用来干什么、不能用来干什么"。

示例：
> ① 真实公开数据：来自 [来源清单]，共 [N] 个来源、[M] 条已核实指标，逐条可溯源。
> ② 模拟数据：[说明为什么必须用模拟数据、规模是多少、注入了多少已知异常]。
> 边界：[明确写出哪些结论不能从这个数据得出]。

**(b) 每个指标的口径与已知陷阱** —— 逐字段写：业务含义、计算口径、**陷阱**。

**"陷阱"是这一节的核心价值。** 示例（银行领域）：

| 指标 | 陷阱 |
|---|---|
| 平均等候时长 | 存在字段单位错误的极端值（被放大 60 倍），直接算均值会被拉到 400 分钟以上。必须剔除 > 180 分钟的记录并单独统计。 |
| 业务差错率 | **低频计数指标**。日粒度上分子常为 0~2 笔，偏离几乎全是抽样噪声。**必须按周看**（7 天累计）。 |
| 投诉率 | 基线常为 0，**相对变化率会变成无穷大**（0→2 笔就是 +∞）。必须用绝对增量判定。 |
| 业务量偏离度 | **必须按星期几对齐**。周内效应极强（周日只有工作日的 1/3），用 7 日滚动均值做基线会让每个周日都显示 -65%，即每周制造一次假异常。 |

**(c) 分析纪律** —— 几条不可违反的规则，会被"口径守卫"阶段强制执行。

### 3.3 口径守卫（把语义层变成代码约束）

阶段 3 必须**不只是提示模型注意，而是直接改掉错误参数**，并把修正过程展示给用户。

示例（这是真实生效的一条）：
> 当用户问"差错率的趋势"时，Agent 自动把**日度**切换成**周度**，
> 并在页面上提示："差错是低频计数事件，日粒度信噪比过低，已切换为周度口径。"

## 四、操作白名单：定义 6~8 个操作

每个操作包含：`id`、`title`、`desc`、**关键词列表**（用于模板匹配）、
**参数规格**（类型/取值范围/默认值）、`run(params)` 函数、
以及 `interpretation`（给业务人员的解读文本）。

**银行领域我实际做的 6 个**（请按你的领域替换）：

| 操作 | 回答什么问题 |
|---|---|
| `branch_rank` | 哪些网点某指标最高/最低（按指标排名） |
| `weekday_pattern` | 周一到周日业务量怎么变（周内规律） |
| `trend` | 某指标在某区间的趋势、前后期对比 |
| `branch_drill` | 某个网点的完整画像 + 时序 + 该网点预警 |
| `alert_analysis` | 预警按性质/严重度/主因/网点分布 |
| `data_quality` | 疑似字段单位错误、指标间不自洽记录 |

**操作设计要点：**
- 覆盖你领域的**核心问题类型**（排名、趋势、规律、单实体深钻、结构分布、数据质量）；
- 操作之间的产出**不应重复**；
- 每个操作要返回：`kpis`（3~6 个关键指标卡）、`sheets`（工作簿的工作表定义）、
  `charts`（图表定义）、`interpretation`（一段业务解读）。

## 五、七阶段可观测流水线（这是"可视化"的核心）

**用户必须能看见 Agent 每一步做了什么、依据是什么、耗时多少。**
每个阶段渲染成一个可展开的卡片，标题栏显示阶段名 + 耗时 + 状态（执行中/完成/已调整）。

| 阶段 | 做什么 | 页面上必须能看到 |
|---|---|---|
| 1 意图识别 | 模板规则匹配，或（填了 Key 时）调 LLM 路由 | 识别方式、**识别理由**、选定了哪个操作 |
| 2 操作选择 | **白名单校验** | 白名单规模、校验是否通过、参数模式 |
| 3 口径守卫 | 抽取参数并按语义层纪律**自动纠正** | 参数抽取日志、最终参数、**触发了哪条修正** |
| 4 执行引擎 | 在浏览器内计算 | 计算范围、产出工作表、行数、图表数 |
| 5 工作簿构建 | 生成 Excel 规格 | 文件名、工作表清单、格式、**声明已写入** |
| 6 文件产出 | 现场构造 `.xlsx` | 文件大小、是否含宏、兼容性 |
| 7 结果与解读 | 渲染结果并给业务解读 | 解读文本、总耗时、数据性质复述 |

**关键要求：**
- 每阶段之间留 100~160 ms 的可见延时（`await sleep(...)`），
  否则用户看不到过程，只会看到结果瞬间出现，**"可视化"就失去意义了**；
- 阶段内容里要写**为什么这么做**，不只是"做了什么"；
- 在阶段 2、3、5、6、7 各放一个说明框，把关键设计取舍直接讲给使用者看。

## 六、可选的 API Key 输入框

页面上留一个**默认留空**的 API Key 输入框：

- **不填** → 用内置的模板规则匹配，**全程离线**；
- **填了** → 任意问法都能被理解（浏览器直接调 LLM）。

**安全要求（必须同时满足）：**
- Key 只存在 `sessionStorage`，**不写入任何文件、不发给第三方**；
- 页面上**明写这一点**；
- 匹配不到时**明确告知"我答不了"并列出能答的问题类型**，
  **绝对不要硬凑一个看起来合理但无依据的答案**。

## 七、Excel 生成

**浏览器端没有 Python，必须用 JavaScript 现场构造 `.xlsx`。**
推荐 **SheetJS**（`xlsx.full.min.js`，可从 `cdn.sheetjs.com` 获取后内联）。

**工作簿结构（按此顺序）：**

1. **第 1 张表固定是「说明与数据性质」**（强制，不可省略）：
   问题、生成时间、执行操作、参数、**数据性质声明、边界**、分析纪律。
   理由：这样任何人拿到文件都能看到"哪些数能用、哪些不能"，不需要另外查文档。
2. 第 2 张是「结果解读」。
3. 之后是各个数据表，**每张表末尾附一行口径备注**。

**能做到的格式（SheetJS 社区版）：**
- 单元格数字格式：千分位 `#,##0`、百分比 `0.0%`、千分号 `0.000"‰"`、带符号 `+0.0%;-0.0%`
- 列宽自适应 `!cols`
- **冻结表头** `!freeze`（长表滚动时表头可见）

**做不到的（必须如实说明，不要假装支持）：**
- **图表**（SheetJS 社区版写不出图表）

**因此必须补一个交付物**：另用 Python（`openpyxl`）生成一份**带真实图表**的
参考工作簿，并在页面上说明两者的分工：

| 文件 | 生成方 | 能力 |
|---|---|---|
| 网页里下载的 xlsx | 浏览器端 SheetJS | 数字格式、列宽、冻结表头；**不含图表** |
| 参考工作簿.xlsx | Python / openpyxl | 含真实图表 |

并在页面的阶段 5 里**直接把这条边界写给使用者看**。

## 八、验证要求（这一节决定成败，不要跳过）

**网页 JavaScript 不能靠肉眼确认"看起来对"，必须自动化验证。**

### 8.1 Node 沙箱自检（必须做）

写一个 `verify_agent.js`：
1. 从生成的 HTML 里**抽出所有内联 `<script>` 块**；
2. 在 Node 的 `vm` 沙箱里**真实执行**（为 DOM / Blob / fetch 打桩件）；
3. 对**每一个操作**跑真实数据，断言：
   - 产出结构完整（`sheets` / `kpis` / `charts` / `interpretation` 都在）；
   - **关键数值正确**（例如"降序排名结果必须单调不增"、
     "阈值过滤后的记录必须都超过阈值"、"各表行数与全局统计一致"）；
   - 意图路由正确（给定问题 → 期望的操作）；
   - 参数抽取正确（给定问题 → 期望的参数值）；
   - 工作簿规格正确（第 1 张表是数据性质声明、含"模拟数据"字样、列宽已设置）。

**目标：至少 40 项断言全部通过。**

### 8.2 无头浏览器渲染验证（必须做）

用无头浏览器（Chrome / Edge 的 `--headless=new --screenshot`）**真实渲染并截图**，
确认 DOM 与视觉正常。

**为此需要给页面加一个 `?q=问题` 参数支持**（带问题直接打开并自动运行），
这样截图才能拍到流水线跑起来的样子。这个参数本身也是实用功能（便于分享特定问法）。

**这一步能抓到纯逻辑测试抓不到的 bug**——我实际用它抓到了两个布局 bug：
输入框被压扁、柱状图被离群值压扁。

### 8.3 交付前必须检查清单

- [ ] HTML 里**没有任何外部引用**（`src="http..."` / `href="http..."` 应为 0 处）
- [ ] 断网状态下双击能正常跑通全部 6 个操作
- [ ] 下载的 `.xlsx` 能被 Excel/WPS 真实打开，中文不乱码
- [ ] 页面上**每一处声称支持的格式能力都真的做到了**
- [ ] 数据性质声明同时出现在**页面顶部**和**Excel 第 1 张表**里

## 九、必须避开的坑（我实际踩过，请直接照做）

### 9.1 把多行 JS 拼成一行时，`//` 注释会吃掉后面所有代码

内联构建数据/脚本时如果把多行拼成一行，**`//` 单行注释会把它后面的所有代码
（包括 IIFE 的收尾 `})();`）全部注释掉**，整块脚本报
`Unexpected end of input`，后续所有定义（操作数组等）全部失效。

**必须用 `/* */` 块注释。** 这个错误只在拼成一行时才暴露，本地分行看着完全正常。

### 9.2 内联数据里的 `</script>` 会提前闭合脚本标签

把 JSON / base64 内联进 `<script>` 时，数据里一旦出现 `</` 序列
（gzip 出来的随机字节很容易产生），HTML 解析器会**提前闭合 `</script>`**，
导致同样报 `Unexpected end of input`。

**修法**：写入前把数据里所有 `</` 转义成 `<\/`（JS 字符串里等价于 `</`）。

### 9.3 `const` 是块级作用域，`vm` 里取不到

在 Node `vm` 沙箱里**分块执行**脚本时，`const OPS = [...]` 这类声明
**不会挂到全局对象上**，验证脚本取不到。

**修法**：把所有块拼成**一段**脚本执行，并在**末尾追加**导出语句：

```js
;globalThis.__export = { OPS, ROWS, matchByRules, extractParams, buildWorkbookSpec };
```

### 9.4 不要用非贪婪正则切分 `<script>` 块

用 `/<script>([\s\S]*?)<\/script>/g` 切块时，如果脚本里出现
`i<bin.length` 这种比较表达式，非贪婪匹配会在 `</` 处**提前截断**，
把好文件误判成语法错误。

**修法**：顺序扫描——从前一个 `</script>` 之后找下一个 `<script>`。

### 9.5 前端格式能力不要过度承诺

SheetJS 社区版**写不出图表**。如果你在页面上写"含条件格式色阶"但实际没做到，
就是空头承诺。**只写你真的做到的能力**，做不到的明确说明并给出替代方案。

### 9.6 布局：不要给全局 `button` 设 `min-height`

给所有 `button` 设 `min-height` 会把页面里其他按钮一起撑开，
在 flex 行里**把输入框压扁并造成元素重叠**。
只给需要的按钮（如 `#run`）单独设 `align-self: stretch`。

### 9.7 图表要处理离群值

如果一组数据里有一个远大于其余的离群值，**柱状图从 0 起画会把其余柱子压平**，
完全读不出来。

**修法**：检测离群（最大值 > 次大值 × 1.6）时改为**截断 y 轴**，
但**必须在图上标注"纵轴未从 0 起，差异被放大显示"**——这是图表最低限度的诚实。

### 9.8 中文环境的工程坑（Windows）

- `cmd.exe` 按控制台代码页解析 `.bat`，中文注释会让语法解析失败 → **`.bat` 写纯 ASCII**；
- Windows PowerShell 5.1 对**无 BOM** 的 `.ps1` 按 ANSI 解析，中文变乱码 → **存 UTF-8 with BOM**；
- **不要把中文文件名作为参数传给 Python**（代码页转换会破坏参数）→ 让脚本自己按目录发现文件；
- Python 脚本入口要 `sys.stdout.reconfigure(encoding="utf-8")`，
  否则 `print("✓")` 之类会抛 `UnicodeEncodeError` 中断执行。

## 十、交付物清单

1. `results/<你的领域>Agent.html` —— **单文件、离线可用的 Agent**（主交付物）
2. `results/参考工作簿.xlsx` —— 带真实图表的 Excel（补足浏览器端能力边界）

5. `src/py/build_web_agent.py` —— 组装单文件的脚本（应能自动补齐中间数据）

**构建链必须是自愈的**：`build_web_agent.py` 发现中间数据缺失时应自动调用
`build_web_data.py`，而不是直接报 `FileNotFoundError`。

| 第 3.2 节 (b) 的陷阱表 | **你领域里每个指标的真实口径陷阱** |
| 第 3.3 节的口径守卫示例 | 你领域里一条"必须自动纠正参数"的规则 |
| 第 4 节的操作表 | 你领域的 6~8 个操作（覆盖排名/趋势/规律/单实体/结构/质量） |
| 第七节的工作簿表名 | 你领域的表名 |

## 一带而过会失败的地方

**第 3.2 节 (b) 最容易被敷衍过去**，但它决定整个 Agent 有没有价值。

如果你的领域没有"指标陷阱"，那说明你还没想清楚——
**任何真实业务数据都有口径陷阱**。举几个非银行的例子：

- **电商**：GMV ≠ 成交额（含未付款/退款）；转化率的分母是"访客"还是"会话"？
- **内容平台**：播放量含重复播放吗？互动率的互动是否含"点赞后取消"？
- **物流**：签收时效算自然日还是工作日？节假日怎么算？
- **医疗**：治愈率的分母是"出院人数"还是"入院人数"？（这两个数差很多）

**先把这些写清楚，再动手做界面。** 否则你会做出一个能跑但没人信的东西。

## 如果对方只能做一件事

让它**先只做第八节的验证**——先写 `verify_agent.js`，
哪怕 Agent 还没写完。因为一旦有了验证，后面 6 个坑都会自动暴露；
没有验证，你只能靠肉眼，而这些坑**肉眼全都看不出来**。
